# 同一人物的多造型与发型差异化

用于同一人的多套肖像、全身妆造、发型试款与造型展示组。用户决定数量、分组、景别与呈现；十套、日韩五套加中国五套只属于[来源案例](../../docs/portrait-look-diversity-analysis-2026-10-15.md)，不成为通用配额。人物转面仍读[同人物资产](character-consistency-assets.md)：同一造型的不同视角保持妆发，本页处理获准设计的不同造型。

## 先冻结不变项，再选择可变项

先确认是同一个人换造型，还是设计不同人物。前者保留本人脸型、五官比例、年龄与辨识点，不借“适合发型”改眼距、削下颌或统一成另一张脸；表情运动与妆面变化单独处理。多人的独立参考身份绑定仍受主入口限制。

正脸、头部端正、不偏头、自然乌黑发色等明确要求是整组不变项，不用歪头、转面、染发、镜头角度或遮脸制造差异。正脸不等于全部表情相同：在固定头位内改变视线、眉睑张力、唇口与面颊动作。原图的刘海属于可改变的造型因素，不能只因保持身份就自动锁住；用户明确保留刘海时才按其范围继承。

将旧基底中固定发型、神态、妆面与姿势的条款按本轮变化范围清理；仍有效的不变项移入共同保持，避免“每根刘海不动”与“完全不同发型”同时生效。检查 composition、proportion 和编辑保护项内夹带的“全部歪头、双手交叠、同一微笑”等旧姿态，不能只清理 action 栏目。所有人物仍执行共同身材美化；近景仅涉及可见颈肩与上身，不证明隐藏全身。

用户要求完整的不同妆造时，逐套联动设计姿势、发型、表情和妆容，并分别验收；换衣服或换发饰不能替代其余差异。只换服装、只试发型或同一造型转面时，仍按已授权通道改变，不擅自扩大。身体基准只继承已核验的比例与体量，不连同基准的歪头、手势、发型、唇口与妆色一起锁住。

冻结新计划前区分关键要求和可调整设计。用户指定的细项继续关键验收；代理自选的分缝侧别、承重侧、微小编节或版面占比不自动升级为用户要求。可在每套 `detail_policy: {critical, reason}` 中列明本轮关键细项，例如 `hair:outline / expression / makeup / action:head / action:hands`；其余仍输出、仍逐项观察，但为 prefer 与非关键检查。每个变化通道至少保留一个关键目标，共同保持与人物基本目标不受此选项弱化。未声明 policy 的历史用法保持原来所有细项为关键。已出图后不能改 policy 回写旧通过；确需调整艺术方案须另建完整计划、说明理由并重新实际生成，旧标准、输出和失败保留。成组差异仍按所有请求通道逐对复核，不用偏好级别掩盖整组无区别。

## 姿势独立设计，头部默认端正

多妆造展示默认头部端正，不沿用一组同方向的歪头形象。明确要求倾头或特定动作时按该项执行；更换倾斜方向、转脸或镜头角度不能单独充当造型差异。头位可以全组保持端正，姿势差异来自肩胸朝向、躯干动势、手臂手势和重心支撑，动作与各套衣装、性格和情绪相合，不为凑变化而夸张摆拍。

每套写清头部朝向及是否倾斜、肩胸与躯干、手臂与手势、重心和实际支撑；上身近景只写可见动作，不臆测画外腿脚。侧转、移重心或屈膝后回查身体体量、关节和接触，不把姿势引起的投影变化当作新的身体比例。全身仍执行[共同身体路线](full-body-baseline.md)的逐人物六区检查。

先说明身份图在本轮保留哪些维度，再明确获准重新设计的维度。原图的双辫、碎刘海、浅妆或笑容不因身份保持自动继承；用户明确保持的妆容与局部编辑边界仍优先。纯文字阶段后来补入身份图时，替换旧原创面容与年龄假设，重新冻结实际原图，不把两套身份条款叠加。

## 先设计脸前结构，再设计扎束与装饰

每套先写以下可见关系，不只填发型名称：

| 区域 | 需要作出的设计决定 |
| --- | --- |
| 额前分区与露额 | 中分、偏分、侧向、后梳等实际走向；哪些额部留白，发根如何衔接 |
| 刘海结构 | 有无刘海、长度、厚薄、边界形状、开口与落点；不让所有造型都继承同款中央细丝与两侧长鬓发 |
| 鬓角与耳侧 | 双侧或单侧露耳、贴合或离开面颊、长度与体积；额前和鬓角形成什么脸周开口 |
| 正面轮廓 | 短发、齐颌、肩部或长发的可见宽窄、直曲和体积；不要把只在背面不同的扎法当作正面已经不同 |
| 后部与附件 | 扎束位置、辫数、发髻构造与固定点；发夹、丝带和发饰服务既定结构，不能独自承担差异 |

自然细发是细节层，不是所有方案共用的一张遮脸纹理。每套可以保留不同位置的少量边缘细发，也可以采用干净露额与清楚鬓角；继续遵守[发型自然度与面部可读性](../core/hair-frequency-variation-v2.md)。用户没有要求遮脸时，不用密集碎发补“氛围”。

刘海要同时写落点和边界：要求眉上时，发梢实际停在眉上并留下连续可见眉形；“薄”描述厚度与束间留白，不等于把细丝留长到眉间。齐切侧片的下缘相对嘴角、下颌角和肩部明确定位。检查主发片与边缘细发分别是否到位，不用更密的细丝网修复未形成的平短边界。高马尾、环髻等先按最高及最外侧发束安排取景，补留白时等比调整人物在画面中的大小，不裁掉发型或单独缩头。

脸型、五官与发型适配应写出本人物的观察和设计理由：额部留白、脸周宽度、颧颌转折、眉眼可读性与发量如何协调。角度和遮挡不足以判断时保留未知，不以“某种脸型只能某款刘海”的公式代替观察。适配通过改变发型、妆面和表演实现，不越权修改稳定五官。

## 联动表情、情绪与妆容

情绪名后要有实际表演：视线落点、眉毛与眉间、眼睑开合、嘴角及唇口状态相互配合。例如含笑可有柔和眼睑和轻提嘴角，专注可有明确视线与收敛唇口；不是全部换一组“清冷、温柔、元气”标签却仍凝视、微张唇。情绪不要求夸张，不靠换脸、歪头或所有人露齿笑证明变化。

妆容按本人的肤色、角色与所选发型分别写眉妆、眼线眼影、腮红位置、唇色边缘及光泽。发型、妆容与神态形成连贯方案，不机械穷举互不协调的组合。用户只要换发型时，妆容、表情仍可固定，不能强行改成全套改妆。

用户要求全套妆面与表演差异时，先比较最接近的方案。多套浅妆不能只将“蜜桃粉、玫瑰粉、豆沙粉”换名而保留相同范围、浓淡与润唇；按当前人物选择可见的眼妆重心、腮红区域、唇色深浅或光泽差异，不强迫每套浓妆。细微情绪同样要有能读出的眉睑与唇口差别，闭唇检查唇面接触与牙齿是否隐去，微张唇检查实际口形；没有动作证据时只记情绪不足，不用标签解释为成功。

## 实图反馈后的修订

先用能暴露本任务风险的代表款检查脸前结构、妆面与表演；参考惯性仍明显时先修关键失效处，再扩展其余任务。用户指定的交付数量继续保留，不把代表样本通过当成整组完成。

拼板反复继承同一歪头、刘海或浅妆时，先检查实际输入是否仍用旧整板承载所有维度；可拆成同身份、共同身体来源的独立单张，逐张只修当前失效通道，再成组复核。此做法是可测试的路线，不保证单张或局部编辑必然有效。不要为通过而事后放宽已冻结发型边界；选择新的艺术方案时明确另立目标，保留旧失败。见[本轮13次实测](../../docs/portrait-look-posture-validation-2026-10-18.md)。

修订从当前完整造型方案出发，只更新本轮获准通道，继续发送仍有效的整套发型、衣装、妆面、头位和身份要求。不得用一个重新撰写的“重点”段落替代其余新造型，或让“其余保持”回指到原身份图的旧双辫、旧衣装与旧笑容。将当前重点栏目提前即可，先清理冲突和冗余，不逐轮叠加同义指令。计划阶段用`revisePortraitLookPlan`更新指定方案的完整通道，继承其他方案及基底；`focus_channels`只移动已有栏目，不另造摘要，也不提供图像控制。生产brief已经补入实际身份图、每套衣装或其他要求时，使用[生产修订器](production-execution.md#修订与多轮意图)更新这份当前brief，不从较早计划重建而丢失后加内容。

改表情后重新检查刘海和主发型，改刘海后重新检查眉眼可见性、唇口和衣装，改取景后检查最高发束与可见比例。回退时保留旧图并说明选取理由；新图时间更晚不构成替代资格。沿用同一个问题键记录实际改善、未变或退步，改写提示词、目标摘要变化或改名不重置连续失败。两轮无明确改善时执行[主入口的停止规则](../../SKILL.md#效果与停止条件)，下一方案须有实际可用的新控制或诊断依据；不能只声称有遮罩、适配器或身份锁定能力。

冻结前逐项核对编辑范围是否确实包含正文请求的操作。不要将多句修改截取第一句作为 `edit_scope.changes`，造成正文要求改刘海、妆面，而末尾只允许回正头部。全身图无法辨认细妆时，可在同张输出增加对应近景，新增取景权限与近远景一致性检查；近景通过不能代替全身发型，重新生成的近景也不能当作旧图的无损放大证据。

## 用户要求流行款时先查来源

用户明确要求流行、最新、某地区或时代的发型时，实际检索当地造型师、沙龙作品、品牌目录或有出处的编辑资料，记录链接、检索日期、可见结构与借鉴范围。用多个来源覆盖所需分组，按本人物的脸型、发质、发色、用途和媒介筛选，不将搜索结果数量或网页标题当作趋势排名。单一日本目录不能证明中国或韩国同期流行。

地区标签是本轮造型分组，不是人物族群或发型专属起源。不足以验证当下流行时明确为设计建议；默认不替用户染发或照搬作品模特的五官、妆色和拍摄姿态。[HOT PEPPER Beauty 目录](https://beauty.hotpepper.jp/catalog/)可按长度、脸型及发质等条件选款；[Milbon 的造型示例](https://salon.milbon.co.jp/shop/pages/hairs-articles-012.aspx)可用于观察发根、额前分束与轮廓的组织，不能据此认证某人物适配或生成效果。

## 成组预检与生成后复核

先内部整理每套的不变项、额前与脸周设计、后部构造、妆面、情绪和可见动作，再横向比较。数量、分组或任务要求不同，依本轮决定，不固定“每套必须改几项”。删掉发型名与地区名后，若仍是相同额前结构和表演，仅后脑扎法、发饰或衣服不同，就不能按“完全不同的脸前造型”交付。

`node scripts/portrait-look-plan.mjs --input plan.json --format json` 可检查数量、可选分组和作者声明的脸前结构、表演、妆面与身体动作是否重复；`--format text` 输出各套完整提示词。基底包含身份、取景、媒介、身材和其他固定要求；可变的 `hair`、`expression`、`makeup`、`action` 通过各套方案写入，固定发色等放在 `shared`。完整妆造差异任务选择这四个通道；局部试款仅选授权通道。JSON由代理编写，不要求用户填写。

工具只比较声明，不理解图像、语义近义词或生理适配；修改内部标签而正文不变仍属未解决。它不能证明发型真的不同、保持同一人或适合本人。`variation_channels` 只列本轮需要变化的通道，防止把换发型擅自扩大为换妆。

每套正文及关键验收分别覆盖身份、实际发型变化、眉眼鼻口可读、指定头位与发色、姿势、表演、妆面及当前身材范围。已知重复先重设计，再按请求逐张生成或生成拼板；有拼板时逐格检查头位、手势与重心，并横向比较脸前结构、眉睑唇口和妆面。相似发型重设计额前与脸周，相似姿势重设计躯干和四肢；不能只改标签、歪头或重抽细发。缩小的全身脸看不清眼线、腮红和唇面时记录未决，查看原尺寸或补对应近景后再评审；身材通过不等于妆造差异通过。

最终交付每套完整可复制正文，不能让用户从“共同模板+第几项增量”自行拼装。需要图像时，各套使用同一明确身份基准，不沿上一套递传未核实的妆发与面容。保留失败、未知与旧目标；文字预检通过不记作视觉成功。

单张符合目标与整组彼此不同分开判断：主轮廓不同不自动代表刘海、妆面、表演或姿势也不同。程序 `portrait-look-review.mjs --input review.json` 回验已冻结快照、实际图片摘要和逐项回执，绑定每一对选定版本的人工差异观察；每个请求变化通道必须已有该套的 must 目标和关键验收，不能事后给未冻结的姿势补一个“不同”。旧图换成新图后，旧版本的比较记录不能沿用。缺少比较或不确定时保持待审，观察为相似时需修订；不能靠不同文件名认作不同造型。该脚本目前按独立输出比较，单张拼板须另存逐格位置、输出摘要及通道观察，不能把同一图片虚报为多次生成。交付浏览候选可带失败项；标为可用成品则各张必须通过冻结的关键检查。实际来源、选择、比较与问题历史字段见脚本的 `reviewPortraitLookSet`，JSON由代理生成。

复核输入含 `plan_id`、`look_ids`、`variation_channels`，以及以下记录；文件路径相对复核JSON，回执里的输出路径继续相对回执解析。

- `runs`：每次实际输出的 `{look_id, snapshot, receipt}`，不把只准备而未派发的快照计作图片。
- `selection`：`{look_id, run_id, role, reason}`，`role`为`candidate`或`deliverable`；后者要求该张关键检查全部通过。选择旧版时保留理由与新版失败。
- `comparisons`：`{channel, pair, verdict, evidence}`，`pair`是两个当前选定的运行ID，结论为`distinct`、`similar`或`uncertain`。每个请求变化通道分别记录；未比较的配对自动列为缺失，不强行补造观察。
- 可选`issues`：`{look_id, key, observations}`。每项观察绑定`run_id`、`criterion_ids`、`progress`和具体证据，沿连续父版本排列；首项`initial`，后续为`improved`、`unchanged`或`regressed`。停止决定基于这份人工进展记录，不从提示词长度或文件名推断。

CLI退出码0表示记录中的关键检查和差异比较均支持观察者通过，2表示记录有效但需修订或复核，1表示输入、来源或摘要错误。它不调用生图工具，不证明用户接受，也不自动查看图像；`stop_current_routes`提示调用方停止对应问题的旧修订路线。

本轮[18次实际生成与优化证据](../../docs/portrait-look-execution-2026-10-15.md)说明这些门槛的必要性，不证明新增规则已经解决模型中的刘海或情绪控制。

## 工具中的权威设计字段

hair.front 的 parting、fringe、temples、outline 分别填写可见中文设计，禁止用内部签名代码代替。四项各自进入最终正文、must 要求和关键验收，同一份设计也用于查重；修改刘海会改变交付正文和目标摘要。hair.text 只补充后部扎束、附件与衔接，不再重复填写四项脸前设计。基底可保留带 character_goal 的通用自然度与可读性要求，它们不锁死每套的分缝或刘海；其他旧发型、妆容和神态锁定仍须清理。

action 的 head、torso、hands、support 分别填写上述四类可见姿势设计，各自进入正文、must 要求与关键验收。查重比较 torso、hands、support 的共同声明，故只改歪头或转脸仍报告 `repeated_body_action`；全组头部端正而身体动作不同可以通过。该查重不识别同义改写或实际歪头，实图仍须检查。`revisePortraitLookPlan` 支持仅改 action 并继承当前妆发和表情；没有选择 action 的试发型任务继续保留原固定姿势。
