# 提示词输出质量审查

先核对本轮需求、真正使用的图片及完整正文。程序只定位结构问题；“诊断清空”不证明画面好看、身份正确或文本没有语义矛盾。

## 先解决影响结果的问题

- 主体与本轮操作尽早明确。捏脸注入将身份正文放在基底前，保留原栏目内部顺序；编译器仍原样交付作者正文。身份、妆肤、神态、媒介和光照分别表达，不让“精致、真实”代替具体关系。
- 每个必须目标在对应通道有实际条款与依据。场景与产品不套人物比例；准确文字写完整内容、位置和层级。仅把目标ID挂到别的栏目不算落地。
- 细节按当前取景选取。近脸可描述妆饰位置、唇缘与五官连接；全身优先可辨识锚点、体态、衣型及取景。需要微细妆肤验收时另看适当近景，不因全身文件齐全就确认细妆。明确要求全面细部设计时保留细部，不按固定长度截断。
- 编辑时具体视觉设计放在相应栏目，末尾范围只概括允许区域、操作和保护边界。同一句不能同时声明允许改变与必须保持。新光线与原妆、原光向与亮度整理、换装与原体型各自核对；程序只识别字面相同的冲突，其他矛盾由代理判断。
- 捏脸呈现叠加到已有神态、妆发、灯光或视点时，逐项判断是互补还是替换。需要替换先同步更新旧正文、要求与验收，不让正面/侧面、闭唇/张口等相反目标共同生效；重叠通道本身不证明冲突。

## 定位与修订

```bash
npm run prompt:audit -- brief.json
```

返回 `prompt_sha256`、正文字符与条款统计、实际栏目分布，以及重复正文 `repeated_clause`、范围复述 `scope_repeats_clause`、捏脸呈现重叠 `face_layer_overlap` 的具体位置。没有固定字符上限，不按“越短越好”评分，不运行 tokenizer，也不自动删除、翻译或重排正文。结构编译失败时命令失败；`needs_review` 表示作者需要审阅，互补重叠可保留，`diagnostics_clear` 也仍须通读与看图。

保留所有必须目标与真实来源后，再合并重复或改写范围摘要。新标准化计划可使用 `scope_format: 'compact'`，详细观察、正文和逐项验收均保留；旧计划仍保持原格式。更新正文后重新编译与冻结，旧执行正文、快照、失败和图像不改写。

[完整编辑示例](../../examples/compact-edit-current-prompt.md)仅缩短范围摘要，不删细部目标；它是文本复查，未重出图。新形式能减少复述，但不能据此推断脸部或衣纹保持改善。实图已有同问题两轮无明确改善时继续执行停止规则，保留原图及最佳候选，不能用更短正文无限重试。

## 冻结前处理剩余诊断

prompt-build 和 production-run prepare 都执行同一质量诊断。诊断为空可继续；仍有重复或叠加提示时，先修改实际正文再重跑。确有必要保留的互补或保护条款，用 quality_review 记录 prompt_sha256、diagnostics_sha256、reviewer 和 decisions。每条决定包含对应诊断的 objectHash（diagnostic_sha256）、resolution: retain 及具体 reason，不能用“已修复”跳过仍存在的诊断。

正文或诊断改变后旧记录失效；最终冻结同时保存诊断与处理记录。这里记录作者判断，不认证审阅者、语义或图像。不能机械删除重复、截短正文，或将所有通道重叠当作错误。先解决主体与编辑范围、来源、结构和媒介冲突，再处理表面与锐化；旧优先级编号不替代当前用户范围。
