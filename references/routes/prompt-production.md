# 从需求与参考生产提示词

用户提供描述与可选参考，代理完成观察、设计、撰写和审查。不要让用户填写模板，也不要将兼容素材直接交付为完成的任务。共享约束以 [技能入口](../../SKILL.md) 为准，本页只维护执行步骤。

## 确定本轮目标与范围

识别新图、扩身、换装、换风格或局部修复，确定主体、用途、必须保持与必须改变。纯文生图用 `references: []`；混合画面有本轮需设计或验收的人物时声明 `character`，无人场景用 `scene`，商品用 `product`。人物、产品、环境和准确文字分别读取入口路由，不把人物预设套到所有任务。

当前参考身份契约只支持一个人物及同人补充视角。多个人物分别保留身份的请求应说明当前缺少逐主体绑定，不合并不同人的身份组。简单原创多人设计可按文字处理，但不声称已验证逐人的参考保持。

区分用户必须项与设计偏好。未知但可合理补全的内容直接做克制设计并记录依据；身份来源等核心冲突无法推断时再澄清。要求已完整时先消除矛盾，不继续堆词。人物的自动比例、动作与神态由代理选定，不能把“模型自动选最好看”留作未落地的指令。

## 实际观察与分配来源

逐图查看人物辨识点、商品外形、服装或包装构造、材料、视点、光照、文字及遮挡。只记录影响本轮设计的事实，标明可见、部分可见和未知。近景不证明隐藏全身；文件名、旧提示词和“已出图”不代替观察。已有用户满意图优先校准实际用途，不用便于测量的诊断图替代成片方向。

为参考分配身份、衣装、商品、风格、布局、编辑基准或评价用途。单人物只有一个主身份来源，其他同人视角补可见细节；衣装与风格可另有来源，但不能借用其人物。评价标杆默认只观察。是否同一人物由观察与用户声明判断，身份组不是自动认证。

输入顺序按最终实际送入工具的图片计数。逐图检查 `audit.reference_usage` 的 `input_position`、事实与对应条款；只观察的图片没有输入位置，其信息必须写成独立可执行的文字，不能要求模型“按图二”却只发一张。该清单不识别文字中的错误图序或启用独立参考控制。

## 做具体设计决定

每个关键部分选择继承、改变、移除或设计延展。人物由角色功能、年龄气质、衣装、动作和媒介决定体型；新创作与获准比例优化按 [完美方向](../core/fashion-proportion-system.md#完美方向的正向设计) 主动设计更优的全身轮廓、头肩、躯干、腰臀及四肢关系，不仅列畸形禁令。已认可母图保持本人体型。产品先确定形体、部件与品牌保持，再确定材料、环境与展示方式。文字先确定逐字内容、位置、层级和可读性，再安排视觉背景。

人物的舒展修长美化适用于各年龄、性别、体型与媒介。明确体型保留辨识特征，但仍可适度理想化长度、曲线、体积和姿态；不要因“力量型、丰润、矮壮或Q版”就自动关闭美化。保持原样或窄范围局部编辑时，不借该共同偏好扩大操作范围。

造型、媒介和材料分别处理：白底不自动照片化，精细材料不要求粗糙面容，纸纹不证明绘画风格。换风格清理旧媒介冲突；换背景将必要的人物受光变化纳入允许范围，不能同时锁死旧灯光。衣料、发丝和软组织随动作响应，但不借联动扩大用户保护范围。

新创作只选择一套连贯方案，不叠加互斥的头身、腰线、姿态或风格。缺失区域沿可见构造与主辅色补全，注明设计而非观察。具体方案用 `intent: design` 与 `reason` 记录本轮依据；自己的补全细节不升级成用户不可协商的要求。

## 编写与提交前审查

用无编号中文语义标签组织可复制正文，标签服务实际任务。写清主体、来源、设计、构图、动作、材料、光线、允许变化与保持范围；内部参数留在执行计划。真正画面中的文字逐字保留。局部编辑不机械复述全套生成条款，清理上一轮不适用的操作指令。

代理通读最终正文并回看原始描述与实际参考，逐项检查：

1. 必须项是否有可执行表达及适用的图像验收？是否真实描述本主体，而非通用形容词？
2. 是否同时要求相反的朝向、姿态、背景、光线或媒介？有没有局部修复中的全身重塑？
3. 是否将不可见信息假锁定，混入别人的身份、衣装或未授权配件？
4. 形体、材料、动作、取景是否空间可共存？有没有以缩头、拉腿、裙尾或鞋跟凑比例？
5. 产品标签和文字是否完整可读，精确内容与背景留白是否冲突？
6. 删除重复与无效口号；保留必要结构和控制边界，不以字符数决定提示词是否有效。

“已调用几次”“上一张未通过”等日志不进入生成正文。已知矛盾先修正文，不先花一次生成来确认它。编译只能检查声明与覆盖，不能代替上述语义审查。

## 固定记录与派发

需要持久化或执行时，代理创建 brief：`subject_kind`、`request`、`references`、`requirements`、`unresolved`、`sections`、`acceptance`，可选 `target`、`edit_scope` 和内部 `metadata`。未知顶层字段报错；模型设置只能放在 `target`，内部说明不改变执行。字段、参考权限、稳定身份目标和局部范围详见 [执行契约](production-execution.md)，模型设置详见 [模型指南](../providers/text-to-image-models.md)。

每个必须视觉目标关联出图前固定的关键验收。人物在 proportion 正文引用协调比例要求；明确数字才填 `target_head_count`。近景只检查可见关系，不擅自扩为全身。构图与人体比例分别验收；产品和无人场景不添加人体检查。

```bash
node scripts/iteration-director.mjs prompt-build --input brief.json --format text
node scripts/production-run.mjs prepare --input brief.json --id run-01 --case case-01 --cohort pilot --out run-01.snapshot.json
node scripts/production-run.mjs inspect --snapshot run-01.snapshot.json
```

派发前核对冻结的完整正文、实际输入和模型入口。有运行时长度合同的请求先用实际 tokenizer 检查完整正文及负面，在记录中绑定执行摘要；`dispatch_ready: false` 时停止派发。实际图片输入和正文与交付保持一致，不暗加参考，不用其他模型冒充用户选择。

## 看图、修订与交付

先在正常尺寸看整体效果，检查设计是否适合实际用途、空间与形体是否可信、是否对齐本轮审美。生成前把这些目标写成具体关键验收，而非只检查场景有几件物品、文字是否出现。绘画媒介仍需可信的门窗、家具、通行与光照关系，精细CG仍需完成的人物设计及神态；纹理数量和表面写实不能替代完成度。人物主试产用当前用户标杆；诊断角色单列，不作为标杆方向的成功证据。

用户的拒绝或评分绑定原快照与输出，汇总时使用 `report --user-feedback feedback.json`。原事实观察和冻结评审不改写，生效资格撤回；只记录用户实际分数，未知分数省略。未被评论的其他图不自动认作用户接受。

保存真实输出，按冻结标准记录每项 `pass/fail/uncertain/not_assessable` 的可见证据。人物按身份、媒介、比例、动作、衣装、材料与空间检查；产品与文字按对应路线检查。编辑另逐项比对基准图及保护范围。自然遮挡不是畸形，也不作为隐藏结构已正确的证据。

先修最影响目标的一组问题，写一个可检验的新假设。整体方向正确则局部修复；设计或身体大关系从起点错误时回到原来源重新设计。与上一候选没有明确改善、保护项退步或同一问题连续两轮未改善，就保留最佳候选并停止该路线。默认先试一至两张代表图，最多两轮修订；明确批量与次数要求优先。

每轮重查已成立部分，不以局部收益掩盖越界或关键失败。更换目标、人物或造型另建版本，不算旧目标修复成功。重复图不增加独立成功，同图同标准存在冲突评审时先处理冲突。来源图、不同目标及不同模型不混排“最佳”。

交付可复制正文、实际测试图（执行时）、通过与未决内容。仅提示词说明本轮尚未出图；观察者通过不等于用户接受，单次成功不证明批量稳定。量化分数、修订次数、用户接受、耗时和已知成本按相应实验组记录，未知值留空；历史分母与失败不重置。
