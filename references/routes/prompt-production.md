# 从参考图和描述生产有效提示词

目的不是选择一段模板，而是把用户意图和图像证据转成一次明确、可执行、能检查的生成任务。用户只需提供图和描述；下列分析与记录由代理完成，最终默认只显示提示词和必要说明。

## 1. 理解任务

识别新图、扩全身、改造、风格转换或局部修复。用一两句话在内部确定成功结果：哪一个人物、怎样的形象、什么用途、什么风格、哪些变化必须出现。保留用户的明确要求，不反向用当前默认值覆盖用户。

将要求分为必须满足与偏好。身份、指定服装、指定背景/画幅/朝向、禁改项通常是必须项；未明确指定的袖量、细节密度、光泽等可用专业判断决定。不要把自己的具体补全方案提升为不可协商的用户要求。跨轮保留已确认的意图，本项目已选择 P9 时，不因一张比例失败改成七头身。

描述已经完整时先去冲突，不再堆词。描述很短时补充有用的构图、结构、材料和动作，不增加无关人物、配件、叙事或配色。需要一次假设就能推进的选择可直接决定并记录；多个身份来源互相矛盾时必须先厘清。

## 2. 实际观察参考

为图片分配引用顺序与权限。身份只有一个主要来源，衣装和风格可有不同来源。评价标杆默认不送入生成模型，更不能借走它的脸、发色或头饰。图像工具输入顺序必须与最终正文一致。

同一人物可补充侧面或其他清楚视角，由主参考确定身份，辅助图只补足该人物被遮挡的信息。用身份组记录关联；没有同人依据时不自行融合五官。只凭风格相似的图不能认作同一人。

逐图记录有辨识力的证据，而非一串通用形容词：

- 人物：脸型轮廓、眉眼关系、面颊与下颌过渡、嘴唇/嘴角、表情气质。全身小脸或侧脸造成的不可判断单独注明。
- 头发：发色、主发束走向、盘束位置、轮廓、碎发和饰物固定位置；不能把所有黑发女性写成同一花髻。
- 服装：领口与闭合方式、内外层关系、腰部结构、袖型、衣片连接、纹样所在区域、主辅色比例。先有结构，再写装饰。
- 材料：以厚度、反光宽窄、透光、褶皱、织纹和边缘为证据，区分看见的表现与推定的材质名称。暖色环境光不等于衣服本身全是金色。
- 布局：人物姿态、透视、遮挡、裁切；哪些是要移除的原场景效果。只看见近景时，不声称观察到了鞋、腿长或完整裙摆。

选择影响这次成败的证据即可。重复背景叙述与无关花枝不进入白底资产正文。

## 3. 做可执行的设计决定

对每个关键部分决定：继承、改变、移除或补全，并有用户要求/观察事实/合理设计的依据。

**身份和美感**：保留本人的辨识点，避免用“统一鹅蛋脸、大眼、高鼻、小下巴”重造所有角色。按 [妆容与肌肤](../core/makeup-skin-integration-v2.md) 先建立精致、贴合角色的妆面，再用柔和分区反射、眼睑与软组织、适量局部纹理体现真实感。纹理强度服从妆容、美感和景别，不为增加真人感牺牲吸引力或引入疲态；全身小脸不强行显示毛孔。将本轮妆容色彩、浓淡、光泽与肤质尺度写入【妆容与肌肤】，不能只追加“超真实皮肤”。

**表情按任务适配**：按 [表情与身份区分](../core/identity-vs-temperament-diagnostics.md) 结合人物气质、姿态、背景和用途选择眼神、眉眼张力、嘴角和唇部开合，保留身份而允许自然表情运动。用户明确表情或视线要求优先；不统一微笑、不堆叠矛盾情绪、不自动改变头部朝向。局部改表情时删除旧“锁定原神态、嘴角位置”等冲突文字，保持年龄、造型、构图和布光；仅修其他部位时不顺带换表情。

**发型为面容展示适配**：用户允许自动调整时，保留发色、发长方向、主要盘束轮廓与身份相关饰物，按五官和姿态安排分缝、鬓发及束发位置。大幅收拢或移开横跨额头、眉眼、鼻口和面颊的碎发，眼睛与鼻口清楚可见；保留少量脸廓外发丝、发束层次与自然蓬松度。不要逐缕锁定原图的风吹乱发，也不要为了干净变成油亮贴头皮。只有用户特别要求复刻刘海或发饰时才收紧对应结构。调整头发遮挡和调整照明是两个可分别检查的目标，不能只去掉发丝投影就说面部遮挡已解决。

**媒介和材质分开**：先判断用户要摄影、轻写实资产还是厚涂原画。再决定服装的材料可信度与细节密度。白底只改变背景与呈现用途，不能自动擦除厚涂面容、选择性边缘和幻想气质。黑金幻想服装也可以是实拍材质，衣服题材不替代媒介判断。

**背景按本次意图选择**：读取 [背景与环境适配](../core/background-direction.md)，支持保留、调整、替换原背景或选择白底/其他棚背景。白底不是定妆照或全身图的必要条件。未要求移除原景时通常保留可用场景；只获“允许调整”不擅自替换地点。逐项说明景物、景深、透视、地面与色调怎样处理，背景与人物照明分开决定。

**补全不是随机加法**：半身扩全身时，沿可见领袖与主辅色推导一个连贯下装，写清内外层、腰线连接、衣摆与鞋的关系。没有依据时选择克制的结构；不自动加战甲、透明层、开衩、满身金纹或大冠。用户允许优化时可以调整可见衣片，但保留明确的角色识别点。

**比例与体型一起设计**：按 [身材比例与体型](../core/fashion-proportion-system.md) 落实本项目修长、匀称、有适度肌肉线条的目标。沿用已选 P9，在【身材比例】中分别写清头身与肩颈、胸廓与腰臀、上下臂、上下腿和肌肉量；线条随动作自然收缩或放松，不额外裸露或让肌肉穿透衣服。不要同时写极小头、长脖子、极高腰和超长腿来叠加拉伸。严格检查各部位协调，不把“黄金比例”当作统一数学公式；裙尾、发髻不算身高，衣带不等于腰围，隐藏关节不可精确测量。用可见身体关系与用户审美目标验收，不能由数字自行判通过。

**动作自动适配并保持生动**：读取 [动作与生命感](../core/action-direction.md)，结合人物、情绪、服装、场景和用途选择一种明确动作，支持日常动作和夸张伸展、跳跃、旋转等。写清动作阶段、身体关系、表情视线与衣料响应；通过自然松紧、不对称、接触和注意力表现活人感。站姿只是其中一类，选用时再读 [站姿决策](../core/standing-pose-direction.md)。当前明确的朝向和取景优先，未指定时允许随动作协调调整；腾空不强制落地，鞋脚仍允许自然遮挡，不以夸张本身判错。

**细节有目的**：材料路线把细节用于厚薄、织物、缝合和反射；原画路线把细节集中于脸和关键装饰，周边概括。主衣片需要安静空间，亮度焦点有主次。每个“高级、华丽、真实”至少对应一个构造或光学描述，不能靠更多同义词强化。

**灯光匹配背景与用途**：选择白底定妆时按 [白底摄影布光](../core/studio-lighting-direction.md) 用大面积扩散主光和充分正面补光，让额头、眼周与双颊均匀受光，去除不需要的斑驳硬影并保留柔和体积。有场景时保留合理的环境光方向、色温关系和反射，可为人物清晰度补光，不强制改成全中性棚拍。替换背景时协调受光与接地；局部改灯光不能同时锁定旧明暗，也不借机重塑五官。背景与面部布光分别建立视觉检查项。

## 4. 撰写与语义审查

最终提示词直接写中文视觉要求，英文参数改写为对应类别中的中文提示词，不附英文模式设置或参数表，也不逐词翻译成中文参数表。把美感优先、写实程度、时装比例、材质细节、亮度重点和边缘虚实落实到相关类别。例如用“妆面细腻完整，皮肤保留柔和体积与克制分区反射”表达面容目标，用“脸部与主饰最清楚，发梢和次要裙边自然柔化”表达细节与边缘目标。内部路线标识只留在计划配置；即使用户输入旧模式块，也先理解其意图再编写正文。

从本轮决定直接组织不带编号的中文语义标签，例如 `【人物身份与面容】`、`【服装设计】`；不加数字、中文序号或优先级编号。角色新图通常适合十类标签，但某类无意义时可以合并；局部编辑只写对象、锁定范围和允许变化。模式代号只保留在内部兼容配置，不进入交付摘要或提示词正文；需要调整时直接描述相应的可见效果。

提交前由代理回看实际图和原始描述，做如下审查，不能由正则表达式代替：

1. 每个必须要求是否在正文中有可执行表达？“服装采集”是否真的写出了这一套衣服，而不是只说高级布料？
2. 是否出现冲突：正面与侧身、保留场景与清空背景、替换背景与锁死旧光线、白底定妆与强制继承场景斑驳光、保留原画与商业真人硬照、局部修手与全身重塑？
3. 是否把未知部位写成“严格保留”？是否从评价标杆偷换了身份？
4. 表面真实程度是否符合用户目标？皮肤、衣料、光线、边缘是否协调？
5. 比例、手部、衣摆和鞋是否空间上可共存？是否为露鞋破坏长裙，或为九头身叠加多种拉伸？
6. 删除重复、相互抵消、模型无法表现的口号；保留能决定结果的具体描述。不追求固定字数或每张相同长度。

审查发现问题先改提示词，不先花一次生成去验证已知矛盾。

## 5. 生产记录与来源检查

需要持久化或执行生成时，由代理创建内部 JSON，不要求用户填写。`scripts/production-prompt.mjs` 导出的 `compileProductionPrompt` 接受：

- `request`：原始描述。
- `references`：`id`、`source`（实际路径/来源）、`inspected`、`generation_input`、`authority`（可控制哪些通道）、`facts`（`id`、`channel`、`visibility`、`text`）。
- `requirements`：`id`、`channel`、`text`、`priority: must|prefer`。
- `unresolved`：尚未解决的关键问题；非空时不得编译为可交付提示词。
- `sections`：独立撰写的 `label`、`channel`、`items`。每条有 `text`、`basis`（要求/事实 id）、`intent: retain|design|remove|constraint`；设计延展另有 `reason`。
- `acceptance`：出图前确定的检查项，包含 `id`、`basis`、`question`、`critical`。

`acceptance` 应检查输出图可判断的目标。“中文标签是否完整”“是否尚未生图”等是文字交付或执行状态，单独留在文本审查记录，不能混入图像成功率。将仅提示词任务升级为生图测试前，先重新核对验收目标并冻结新的记录；不要生成后删除不适用的关键项来制造通过。精确脚位若被长裙遮住，保留不可判断，而整体平衡与衣摆可分别评审。

通道为 identity、expression、action、makeup、hair、costume、material、composition、proportion、hands_feet、background、lighting、style、task、output。身体动作用 action，表情用 expression，背景用 background；旧记录在 composition 中描述动作、identity 中描述表情、lighting/composition 中描述背景仍兼容。动作与构图、神态和材料需联动时按本轮意图一起修改，不机械锁死。可见性为 visible、partial、unknown、not_visible。事实可跨类别提供依据，但参考必须具有控制目标类别的权限。部分可见的事实只描述可见部分。

```bash
node scripts/iteration-director.mjs prompt-build --input path/to/agent-authored-brief.json --format text
node scripts/iteration-director.mjs prompt-build --input path/to/agent-authored-brief.json
node scripts/iteration-director.mjs prompt-review --input path/to/agent-authored-brief.json --review path/to/review.json
```

编译器只检查声明的来源与覆盖，并生成原样正文和 SHA-256。它不知道代理是否真的看过图，也无法证明文字与来源在语义上匹配；这些仍由上面的观察和语义审查负责。`prompt_ready` 不代表效果通过。旧 `asset-prompt` 是无逐图上下文的素材输出，标为 `scaffold_only`。

## 6. 实图评审与修订

已获生成授权时使用宿主图像工具。准确传入声明的实际参考和编译后的完整提示词，保存实际输出；不展示中文却发送英文扩写，不把评价标杆暗中追加为输入。记录输入、最终文字摘要、输出文件摘要、已知工具参数；未知模型或种子填未知，不编造可重复性。

按输入任务确定检查项，每个必须满足的视觉要求至少有一个关键检查项，通常包括：身份与气质、面部方向、整体媒介、比例、姿态/完整取景、衣装设计连续性、材料区别、手脚、背景/光线。每项有可见证据，状态为 pass、fail、uncertain 或 not_assessable。相貌相似不由发色判断，裁切齐全不代表比例通过；白衣没曝光溢出也不代表材质正确。

要求白底时检查输出本身是否为不透明白背景，不能把查看器的白色底板误认为图片已有白底。若工具可读 PNG 元数据或像素，检查 alpha 和四角作为补充证据；白底不合格时保留失败图，按背景范围修复，不擅自把透明资产记作白底通过。外部裙摆、饰物与发丝也需检查是否触框，不能只看鞋和头在图内。

真实记录包括 `prompt_sha256`、`output_image`、`output_sha256`、`inspected`、`reviewer`、`checks[{id,verdict,evidence}]`。`prompt-review` 拒绝缺项或错误摘要，关键失败输出 needs_revision，不确定输出 needs_review，全部关键项被评审通过才输出 reviewer_qualified；永不自动代表用户已接受。

每次先修最影响用户目标的一组问题，并写出一个能检验的假设。例如“侧光和转肩仍像原场景”对应姿态与灯位修订；“全裙都亮而脸弱”对应高光分配；不是失败就把全部词再强化一次。

- 母图整体方向正确、只有手/边缘/裁切问题：在该母图上小范围编辑，保留已通过维度。
- 设计、媒介或人体大关系从起点就错：修正原始提示词，从原参考重新生成，避免在错误骨架上连续补丁。
- 与上轮比较没有明确改善、身份反而漂移、或同一问题连续两次未改善：保留最佳候选，停止该修订路线并说明限制，不无限重试。
- 默认先用一至两张有代表性的图试运行，最多两轮针对性修订；用户已指定批量或次数时按其要求。代表样本不合格时不复制到整批。

交付完整提示词、实际测试图（如果执行）、具体通过和未通过项。不要以程序测试数量替代效果说明。只有一次成功不能宣称成熟稳定；后续在不同服装、媒介和留出参考上积累真实记录，通用化已被多次证实的规则，避免把单图补丁写成全局规范。

实际执行采用 [生成前固定记录与修订](production-execution.md)，确保验收目标不在看到结果后被放宽；视觉证据按 [统一验收口径](../core/visual-acceptance.md) 记录。
