# image-prompt-skill v0.7.1 Implementation Report

Version: 0.7.1
Research/implementation date: 2026-09-26

## Problem addressed

Real output testing showed that “less childish / more high-end” could work, but the model often achieved it through a narrower/sharper face, colder eyes, and a generic mature-beauty template. This is not the same as preserving one character while shifting only facial maturity and temperament.

## Architecture changes

1. Added `facial_trait` reference role separate from `face_identity`.
2. Added Facial Maturity Ladder M0–M4 with M2.5 default for young-but-refined.
3. Added Maturity Signal Router with preferred / limited / forbidden maturity cues.
4. Added Anti-Borrow Guard to stop trait reference leakage.
5. Added Identity Drift vs Temperament Shift classifier.
6. Added Beauty Calibration Rule so “high-end” is driven by presentation before geometry.
7. Added `trait_calibration` repair round with identity geometry locked.
8. Added provider-specific trait-edit notes.
9. Added research notes separating vendor facts, academic findings, and project heuristics.

## Validation

The Node test suite validates role separation, maturity profiles, routing, trait-borrow blocking, and deterministic classification. It does not inspect pixels or prove visual quality.

## Recommended current workflow

A = current Asset Master + identity geometry
B = Facial Trait Reference only
Target = M2.5

Run trait calibration, inspect the result, classify identity vs temperament change, then either lock or run one more small trait patch.

## Not claimed

- No automatic facial-age estimator was built.
- “High-end beauty” is not treated as a scientific facial category.
- M0–M4 is a project control system, not a clinical or biometric scale.
- New prompts require real image A/B testing before promotion to a default rule.
