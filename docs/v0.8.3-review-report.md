# v0.8.3 项目审阅与改进

审阅日期：2026-09-29。范围：当前本地 `image-prompt-skill` 目录与用户标注的“分支 · 分支 · 生成古风角色立绘”对话。当前目录没有 `.git`；此次修改直接落在项目中，未建立仓库或执行提交推送。

## 审阅结论

v0.8.2 的六组目录与三阶段计划已经存在，203/203 自动化测试可复现。因此原实现不是只有方案文档。但技能入口、实际提示词交付与发布验证仍存在缺口；测试通过不能证明已完成真实图像回归。

| 发现 | 影响 | 本轮处理 |
| --- | --- | --- |
| 根目录只有 addendum，没有 `SKILL.md` | 技能缺少标准发现与调用入口 | 新增短入口、界面元数据和按需参考路线 |
| `ancient-white-asset-plan-v082 --face-profile humanized_real_light` 仍输出 `beauty_first_character` | 对话中的脸部 A/B 无法通过 CLI 真正切换 | 新旧资产命令接入配置覆盖，未知参数与缺值报错 |
| 阶段锁仅在 JSON 中，未进入提示词正文 | 复制单阶段文本可能改变已经接受的内容 | 每个编辑输出包含母图、保留项与修改范围 |
| 完整结构阶段同时涉及比例、手与构图 | 小问题可能扩大为整图修改 | 新增 hands/proportion/framing/materials/lighting 局部 focus |
| 已通过维度与计划改动可能重叠 | 计划和可复制指令相互矛盾 | 整阶段冲突标记 `blocked_by_locks` 且不输出提示词；局部编译拒绝重开锁定维度 |
| 交叠手势要求每只可见手五指都清楚 | 遮挡要求矛盾 | 区分解剖上的五指与图像中可见指节，不强制十指全露 |
| 部分面部模板要求统一鹅蛋脸、或指导非面部写实 | 可能覆盖身份或泄漏编辑范围 | 以参考脸型为准，将面部描述限定在面部 |
| 四层材质提示词可能添加参考中没有的金纹、纱 | 材质修复可能变成设计重做 | 仅处理参考中存在的材料与饰件 |
| 默认年龄和 face profile 自带年龄可能不一致 | 换脸部真实程度时连带年龄变化 | 有效年龄由独立 guard 决定，A/B 保持年龄不变 |
| 当前清单只列路径，遗漏 v0.8.2 清单 | 未验证文件变化与实际库存 | 当前清单从磁盘重建，包含 SHA-256、明确排除规则和版本一致性检查 |
| `docs/verification.json` 带有 npm 控制台头 | 无法作为 JSON 读取 | 移除日志前缀，保留历史验证结果 |

## 仍需真实图像验证的部分

下一次实际生成可使用同一参考图做脸部 A/B，然后在已接受母图上分别测试手部、材质或灯光。人物身份、九头身观感、可见手部结构及布料层次由真实图像比较判断；无法看清的区域标记 `not_assessable`。本轮没有声称视觉效果已改善或批量稳定性已达标。

历史脚本与版本报告保留兼容，未进行全面重构；新资产工作流的严格 CLI 校验不代表所有旧命令已获得同样的参数校验。当前目录未安装到全局技能目录。
