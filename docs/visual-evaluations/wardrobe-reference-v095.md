# v0.9.5 身份与服装双参考实测

2026-09-29。用户已允许服装与造型适度优化，本轮测试：原始头像负责人物，指定优秀效果图负责衣装，具体文字改案优先于两图的服装细节。新增三张图，使用内置 `image_gen.imagegen`。

## 比较设计

- A：仅输入原图 2；从用户之前银发白紫长裙优秀图提取具体衣装描述，该优秀图仅供评审。
- B：原图 2 与同一银发优秀图一起输入；与 A 保持相同衣装正文，只改变参考职责前缀并增加衣装图。明确不借银发、发髻、长簪、额饰、面容及身体比例。
- C：原图 8 与新一组黑金优秀图 4 一起输入；正文与 cycle03 的 `b-08-layered-black-gold` 一致，仅增加衣装参考图与职责前缀。它使用历史基线，不能声称同一模型参数或固定种子下的受控比较。

实际输入列表、完整文本和共享正文散列均保存。B/C 的优秀图是实际生成输入，不能再标成 evaluation-only，也不能将效果归结为纯文字提示词改善。

## 落入 skill 的改进

新增 `identity_A_wardrobe_B` 规划场景，明确 A 的身份和头发职责、B 的衣装职责、具体改案的优先级，以及需要单独检查的发色、额饰、面容、身体比例和多余饰物。它与既有 `style_A_asset_B` 的含义不同；后者仍用于风格还原并保留 B 资产母图的服装。

`reference-authority --scenario identity_A_wardrobe_B` 返回参考规划与可用的职责文本，不生成完整角色方案，也不执行图像任务。`style-intent-plan` 拒绝误用此场景，防止输出“B 是身份母图”的反向指令。规划里的数值不是图像模型权重，文本职责也不保证模型遵守。

多参考作为按需选择：具体衣装结构难以仅靠描述传达时可试；已有原图加文字候选足够好时不强制增加图片。增加后保留旧候选，分别检查身份、衣装与本轮文字约束，不能把新增参考的作用混入纯文字实验结论。
